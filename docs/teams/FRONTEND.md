Для улучшенного выбора блоков с DOM-деревом подготовлен экспериментальный прототип UX-004 по `/scout/ux-004` на существующем редакторе. Пользовательский проход и окончательное оформление/продуктовый FE-005 ещё не приняты. [Протокол и наблюдения](../UX.md#прототип-ux-004-от-9-ноября-2026-года).

## Кто делает первым и что дальше

Начать с **UX-004** на действующем экране: прототип связанного выбора «снимок ↔ дерево ↔ инспектор», исправление слишком широкого выбора, клавиатура и узкий экран. Результат пользовательской проверки ещё нужно получить. SYSTEM реализовал и проверил [API-004 v1](../API_CONTRACT.md#api-004--dom-дерево-снимка): ветви, узел/предки, окно соседей и поиск. Использовать работающий API при проверке сценария; замечания по данным передать SYSTEM, не ждать финального визуального оформления.

Затем **DES-006** оформляет согласованное взаимодействие в темах ERGOMS. После согласования данных — **FE-005**, развивая существующие компоненты. Порядок подключения: API-002 `ready`/HTML и `tree_version` → корни → ветви при раскрытии → узел/предки при клике в снимке → поиск по всем узлам → проверка правила API-002 с версией. Маршруты работают и проверены на живом Django/Celery. Условные примеры годятся для макетов, интеграция проверяется с реальными UUID/версиями/курсорами. Поиск охватывает и не раскрытые в клиенте ветви; дерево загружается частями. **FE-004** проверяет новый полный сценарий с настоящим API. UX-003 для ручного режима и базовый UX-001 заново не переоткрывать.

Прочие подключения идут по FE-001–FE-003: сервер ИИ, профили прокси и серверная пагинация уже готовы. Приоритет между этими подключениями и новым инспектором определять явно; наличие нового дизайна не означает завершения остальных клиентских задач.

Для FE-002 использовать ошибки `cloudflare_challenge`, `yandex_captcha` и `captcha_required`. Показывать `error.detail` или `error_summary` и отмечать частичный результат. [Контракт](../API_CONTRACT.md#anti-001anti-002--обнаружение-страниц-проверки).

## Границы

Код — `client/**`, включая переводы; документы — UX.md, DESIGN.md и согласованные макеты. Применять тему и компоненты ERGOMS. Изменение общего ядра оформлять задачей его репозитория. Не менять `api/**`, миграции, Python-зависимости, CLI, его корневой `locales/**` и развёртывание. [Правила клиента](../../client/AGENTS.md).

Дерево исходных узлов нельзя восстановить из одного безопасного iframe: классы удалены, часть тегов заменена. Не ослаблять изоляцию и не загружать исходный сайт напрямую ради DOM. Новые данные передавать SYSTEM в API-004; рабочие селекторы по-прежнему проверяет API-002.

При передаче указать задачу, состояния, изменённый контракт, проверку и ограничения. Подробные критерии хранить в общем backlog, не создавать второй список задач в этом файле.
